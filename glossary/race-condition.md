# Race Condition (레이스 컨디션)

**정의**: 여러 스레드/프로세스가 공유 상태에 순서를 보장받지 않고 접근할 때, 실행 순서에 따라 결과가 달라지는 상황이다. 보안 관점에서는 "검사 시점"과 "사용 시점" 사이에 상태가 바뀌어 보호 로직이 무력화되는 경우가 핵심이다.

**왜 문제가 되는가**: 정상적인 순서를 가정하고 짠 검사 로직(권한 확인, 인증 등)이, 그 검사와 실제 사용 사이의 아주 짧은 틈을 공격자가 파고들어 상태를 바꿔버리면 검사 자체가 무의미해진다.

**간단한 예시**:
```
스레드 A: 사용자가 이 파일의 소유자인지 확인 (통과)
스레드 B: 그 사이 심볼릭 링크를 다른 파일로 교체
스레드 A: "확인된" 경로로 파일을 열지만, 실제로는 교체된 다른 파일이 열림
```

**이 저장소의 예**: [CVE-2021-3560](../vulnerability/linux/CVE-2021-3560-polkit-dbus-race.md) (polkit이 D-Bus 조회 실패를 root로 오인)

**관련 개념**: [TOCTOU](toctou.md)는 레이스 컨디션 중에서도 "검사(Check)와 사용(Use) 사이의 시간차"에 특화된 패턴이다.
