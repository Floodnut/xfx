# Sandbox (샌드박스) / Sandbox Escape (샌드박스 탈출)

**정의**: 샌드박스는 신뢰할 수 없는 코드(웹페이지의 JS, 컨테이너 안의 프로세스 등)를 격리된 실행 환경에 가둬서, 시스템 자원에 대한 접근을 제한하는 보안 경계다. 샌드박스 탈출은 그 격리를 뚫고 나가 바깥(호스트 OS, 상위 프로세스 등)에 영향을 주는 것을 말한다.

**왜 문제가 되는가**: 브라우저의 렌더러 프로세스, 컨테이너의 프로세스처럼 "신뢰 안 되는 코드가 도는 곳"은 애초에 강력한 코드 실행 취약점(UAF, 타입 컨퓨전 등)이 있어도 샌드박스가 피해를 그 안으로 가둬준다는 전제로 설계된다. 샌드박스 자체가 뚫리면 이 마지막 방어선이 사라진다.

**간단한 예시**: 브라우저는 웹페이지의 JS를 "렌더러 프로세스" 안에서만 돌리고, 파일 시스템 접근 같은 건 별도의 더 신뢰된 "브라우저 프로세스"에 IPC로 요청하게 한다. 렌더러가 이 IPC 경계 검증 로직의 버그를 이용해 브라우저 프로세스 권한으로 임의 동작을 시키면 샌드박스 탈출이다.

**이 저장소의 예**: [CVE-2019-5736](../vulnerability/opensource/CVE-2019-5736-runc-proc-self-exe-escape.md) (runc 컨테이너 탈출), [CVE-2026-15113](../vulnerability/browser/CVE-2026-15113-chrome-android-autofill-uaf.md) (Chrome, UAF를 통한 샌드박스 탈출 가능성)
