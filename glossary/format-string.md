# Format String (형식 문자열 취약점)

**정의**: `printf` 계열 함수는 첫 번째 인자(형식 문자열)에 있는 `%d`, `%s`, `%n` 같은 지정자 개수만큼 이어지는 가변 인자를 읽는다. 애플리케이션이 사용자 입력을 형식 문자열 자리에 그대로 넘기면, 공격자가 이 지정자를 직접 채워 넣어 원래 없던 인자를 읽거나 쓰게 만들 수 있다.

**왜 문제가 되는가**: `%x`/`%p`는 호출자가 넘기지 않은 스택/레지스터 값을 그대로 읽어내 정보를 노출시키고, `%s`는 그 값을 문자열 포인터로 취급해 역참조하다 크래시나 메모리 읽기로 이어질 수 있다. `%n`은 한 술 더 떠서 지금까지 출력한 문자 수를 "호출자가 넘긴 포인터"에 그대로 쓰는데, 그 포인터 자체를 공격자가 형식 문자열을 통해 조작할 수 있으면 임의 주소에 임의 값을 쓰는 것과 다를 게 없어진다.

**간단한 예시**:
```c
/* 취약: 외부 입력이 형식 문자열 자리에 온다 */
printf(user_input);

/* user_input = "%x %x %x %x %n" 이면
   printf에 실제로는 안 넘겨준 스택 값들을 %x로 읽어내고,
   그중 하나를 주소로 삼아 %n이 그 주소에 값을 써버릴 수 있다. */

/* 안전: 외부 문자열은 %s의 데이터 인자로만 전달 */
printf("%s", user_input);
```

**이 저장소의 예**: [CVE-2012-0864](../vulnerability/linux/CVE-2012-0864-glibc-vfprintf-nargs-integer-overflow.md) (glibc `vfprintf`) — `_FORTIFY_SOURCE`가 바로 이 형식 문자열 결함(특히 쓰기 가능한 메모리의 `%n`)을 막기 위해 도입한 방어 장치를, 별도의 정수 오버플로우로 무력화하는 사례.
