## HTTP Request Smuggling (HTTP 요청 스머글링)
**정의:**  
프론트엔드 서버(로드밸런서, WAF, CDN 등)와 백엔드 애플리케이션이 HTTP 요청의 경계(Boundary)를 서로 다른 규칙으로 해석함으로써, 하나의 요청이 두 개로 분리되거나 숨겨진 요청이 정상적인 다음 요청과 혼동되는 취약점입니다. 주로 `Content-Length`와 `Transfer-Encoding: chunked` 헤더의 충돌에서 발생합니다.

**보안 영향:**  
- 권한 우회 또는 특정 URL/메서드 접근 차단 회피
- 캐시 포이즈닝으로 인한 데이터 위변조, 피싱 페이지 배포, 비즈니스 로직 조작
- 세션 하이재킹, CSRF 토큰 탈취, 백엔드 서비스 가용성 저하
- 보안 장벽(WAF/방화벽/Gateway)의 감지 및 차단 로직 우회

**대응 방안:**  
- 프론트엔드와 백엔드 간 HTTP 파싱 우선순위(`CL` vs `TE`) 명시적 동기화 및 검증 정책 통일
- 충돌 시 요청 전체 폐기(Drop) 또는 `400 Bad Request` 반환하는 엄격한 메시지 처리기 사용
- 현대 웹 프레임워크/미들웨어의 안전한 HTTP 핸들러 적용 및 최신 패치 유지
- 네트워크 트래픽 모니터링을 통한 이상 스미들링 패턴(T0/H2CS/CL.TE 등) 탐지 및 차단
