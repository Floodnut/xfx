## 개요

Linux 7.3은 커널 스레드가 시작할 때 사용하는 루트 디렉터리와 현재 작업 디렉터리를 사용자 공간의 파일시스템에서 분리한다. 커널 스레드는 전용 nullfs 마운트에서 시작하고, PID 1은 별도의 파일시스템 상태로 실제 부팅 파일시스템에 진입한다. 사용자 공간의 경로를 찾아야 하는 커널 작업은 그 상태를 명시적으로 빌려 쓰도록 바뀐다. 핵심은 파일 접근 자체를 금지하는 것이 아니라, 부팅 과정에서 우연히 공유하던 경로 해석 문맥을 필요한 호출 지점에서 선택하게 만드는 데 있다.

## 사전 지식

### 파일시스템 상태와 마운트 네임스페이스의 차이

프로세스가 `/etc/example` 같은 절대 경로를 해석하려면 어디를 루트로 볼지 알아야 한다. 상대 경로에는 현재 작업 디렉터리가 필요하다. Linux의 `fs_struct`는 이 두 경로인 `root`, `pwd`와 파일 생성 마스크인 `umask` 등을 담는다. `CLONE_FS`로 태스크를 만들면 부모와 자식이 같은 `fs_struct`를 공유한다. 이를 생략하면 복사본을 갖는다.

마운트 네임스페이스는 어떤 마운트들이 연결되어 있는지를 나타내는 별개의 구조다. 따라서 `fs_struct`를 분리했다고 마운트 네임스페이스까지 분리되는 것은 아니다. 이번 변경에서도 `init_task`의 마운트 네임스페이스는 초기 네임스페이스다. 바뀌는 것은 기본 경로 해석의 출발점이다. 이 구분은 v7.3의 `init_mount_tree()`와 `rest_init()`에서 직접 확인할 수 있다. 아래 참고 링크의 릴리스 고정 코드를 검증 기준으로 삼았다.

### 사용자 공간을 실행하지 않는 태스크에도 남아 있던 경로 문맥

부팅 초기의 `init_task`는 PID 1이 될 태스크와 커널 스레드 생성 담당인 `kthreadd`를 만든다. 변경 전 `rest_init()`은 PID 1 생성에도 `CLONE_FS`를 전달했다. 커널 스레드 쪽과 PID 1이 동일한 부팅 파일시스템 상태를 공유하는 구조였다. 사용자 공간의 루트 교체가 커널 스레드의 경로 상태에도 영향을 줄 수 있었으며, `chroot_fs_refs()`는 커널 스레드도 순회 대상에 포함했다. 이 전후 차이는 `14adbd5`, `efdece1`의 diff에 나타난다.

한편 커널이 시작하는 사용자 공간 프로그램인 usermodehelper는 실제 실행 파일을 찾아야 한다. 커널 스레드의 기본 루트를 빈 디렉터리로 바꾸기만 하면 이 동작도 끊긴다. 따라서 기본 상태의 분리와 필요한 접근 경로의 보존을 함께 설계해야 한다.

## 변경 분석

### 공유하던 상태를 분리하고 접근 지점을 명시화

```diagram
type: flow
title: 변경 전, 공유된 부팅 파일시스템 상태
direction: down
nodes:
  - id: init
    label: init_task
  - id: pid1
    label: PID 1 생성, CLONE_FS
  - id: threads
    label: kthreadd와 커널 스레드
  - id: fs
    label: 사용자 공간 루트와 연결된 fs_struct
edges:
  - from: init
    to: pid1
  - from: init
    to: threads
  - from: pid1
    to: fs
    label: 공유
  - from: threads
    to: fs
    label: 기본 경로 문맥
```

첫 단계인 `14adbd5`는 PID 1 생성에서 `CLONE_FS`를 제거한다. PID 1이 독립된 `fs_struct`를 얻어야, 이후 자신의 루트를 바꿔도 커널 스레드의 상태를 다시 사용자 공간 루트로 덮어쓰지 않는다.

`32750c7`은 부팅 중 별도의 nullfs 마운트를 만들고 `init_task`의 `root`, `pwd`를 그 루트로 설정한다. nullfs의 루트는 영구적으로 비어 있고 변경할 수 없는 디렉터리다. 커널 스레드는 기본 상태에서 사용자 공간의 파일 이름을 찾을 수 없게 된다. nullfs를 여러 인스턴스로 만들 수 있도록 바꾼 `e435696`이 이 구성을 뒷받침한다.

반대로 PID 1은 `init_userspace_fs()`에서 초기 마운트 네임스페이스의 최상위 overmount를 찾아 실제 부팅 파일시스템으로 이동한다. 이 함수는 PID 1의 `fs_struct`에 참조를 유지하고 `userspace_init_fs`로 기록한다. 즉 **커널 기본 경로 문맥과 사용자 공간 초기 경로 문맥을 별도로 유지**한다. `9a8e296`의 diff와 v7.3 `fs/fs_struct.c`가 이 연결을 보여 준다.

필요한 커널 경로 탐색은 `scoped_with_init_fs()`로 사용자 공간 초기 문맥을 일시적으로 선택한다. 이 범위에서는 `current->fs`를 `userspace_init_fs`로 바꾸고, 범위가 끝나면 원래 포인터를 되돌린다. 사용자 자격 증명을 교체하는 API가 아니며, 커널 모듈을 적대적인 코드로부터 격리하는 보안 경계도 아니다. 헤더 구현이 바꾸는 대상은 파일시스템 상태 포인터다.

릴리스 코드와 도입 패치의 차이도 구분해야 한다. v7.3 `init_mount_tree()`는 전용 마운트를 `knullfs`에 보관하고 해당 루트에 추가 마운트를 금지하며 읽기 전용으로 설정한다. 따라서 도입 diff의 지역 변수 이름이나 마운트 개수를 최종 릴리스의 전체 구조로 그대로 옮겨 설명해서는 안 된다.

## 설계 결정 및 트레이드오프

### 기본 문맥은 비우고 필요한 사용자 공간 접근은 보존

```diagram
type: flow
title: 변경 후, 기본 상태와 명시적 접근의 분리
direction: down
nodes:
  - id: kernel
    label: 커널 스레드 기본 fs_struct
  - id: empty
    label: 전용 nullfs의 빈 루트
  - id: pid1
    label: 독립된 PID 1 fs_struct
  - id: userfs
    label: userspace_init_fs
  - id: scope
    label: 필요한 경로 탐색 범위
  - id: helper
    label: usermodehelper의 fs_struct 복사본
edges:
  - from: kernel
    to: empty
  - from: kernel
    to: scope
    label: 명시적 선택
  - from: pid1
    to: userfs
    label: 참조 유지
  - from: scope
    to: userfs
    label: 임시 사용 후 복원
  - from: userfs
    to: helper
    label: UMH 생성 경로
```

설계에는 서로 다른 두 가지 접근 방식이 있다. 잠깐 경로를 찾는 커널 작업은 범위를 지정해 초기 사용자 공간 상태를 빌린다. 실제 사용자 프로그램을 실행하는 usermodehelper는 그 상태의 복사본을 받는다. `ed4b167`은 clone 인자에 UMH 표시를 추가하고, `copy_fs()`가 부모 커널 스레드의 상태 대신 `userspace_init_fs`를 선택하도록 했다. v7.3에서는 내부 인자가 `COPY_FS_UMH` 등의 플래그로 확장되었지만 선택 원칙은 유지된다.

이 복사 경로는 `CLONE_FS`, `CLONE_NEWNS` 요청과 초기 마운트 네임스페이스 밖에서의 실행을 거부한다. usermodehelper가 원본 상태를 공유하거나 임의의 네임스페이스 조합으로 실행되는 범용 인터페이스로 확대하지 않은 것이다. 이러한 제약은 v7.3 `kernel/fork.c`에서 확인된다.

정책의 비용과 경계는 다음과 같다.

- 기본 공유 유지 대비 명시적 전환 호출의 유지보수 부담, 필요한 경로에서 전환을 빠뜨리면 파일 검색 실패
- 모든 커널 스레드에 새 마운트 네임스페이스를 만드는 방식 대신 전용 nullfs 루트 사용, 경로 문맥 분리에 한정된 효과
- usermodehelper의 독립 복사본 유지, 초기 사용자 공간 상태를 공유하지 않는 생성 제약
- PID 1이 기록된 파일시스템 상태를 떠날 때 과거 루트를 계속 사용하는 대신 실패를 드러내는 정책

마지막 항목은 `validate_fs_switch()`에 구체화되어 있다. PID 1이 기록된 `userspace_init_fs`에서 전환하면 경고를 내고 그 이전 객체의 `root`, `pwd`를 커널의 nullfs 루트로 바꾼다. 이전 루트에서 계속 파일을 찾는 동작을 유지하는 대신, 이후 그 문맥을 사용하는 경로 탐색과 helper 실행이 실패할 수 있음을 받아들인다. 모든 파일 접근을 원자적으로 중단한다는 뜻은 아니다. 이미 획득한 파일 객체나 복사된 상태 전체를 회수하는 구현은 이 함수에 없다.

커널 스레드의 기본 상태가 사용자 공간과 분리된 뒤 `efdece1`은 `chroot_fs_refs()`에서 `PF_KTHREAD` 태스크를 건너뛰게 한다. 사용자 공간의 루트 교체를 위해 커널 스레드의 기본 경로 상태까지 고쳐야 했던 결합을 제거하는 후속 조치다.
